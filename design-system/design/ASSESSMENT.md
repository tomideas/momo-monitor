# 流程评估 · 2026-09-13

整体可行：以项目文件作为用户与 AI 的共享规范，以本机服务负责浏览器保存。它不是 Claude/Codex 的持续连接插件，也不会仅靠粘贴路径自动修改 EXE。

| 用户步骤 | 原有问题 | 调整后 |
|---|---|---|
| a 复制完整目录 | 原数据不区分模板与已使用项目 | template.json + sourceEntry；旧项目先备份，再初始化 |
| b 打开 App 复制提示词 | 临时网址与端口不适合长期工作 | 提示词只使用项目相对路径，AI 直接读取 JSON |
| c 现有软件设计写入规范 | 原数据全为默认值 | 有源码时建立 token、主题、组件来源和映射；EXE 单独不足以完整提取 |
| d 回 App 调整保存 | file:// 不具备普通 fetch 写文件能力 | App 内部本地服务执行保存与版本检查，端口不暴露给 AI |
| e AI 应用最后设计 | 保存后提示词关闭便难以再次复制 | 常驻「应用已保存设计」入口；区分保存与应用报告 |
| f 后续 Vibe Coding | 项目规则没有入口 | 根目录 AGENTS.md / CLAUDE.md 引用最新规范 |

## 关键约束

首次导入：代码 → 规范。人工编辑后应用：规范 → 代码。重新提取时必须比较两者，保护用户尚未应用的修改。不能把这两个方向混成每次连接都自动同步，否则会丢失用户设计。

原服务已有版本检查、原子文件替换、同源写入限制及应用证据接口，本次保留。已删除 AI 接入回执；App 不判断 AI 是否在线。

服务仍按项目目录隔离写入，并拒绝属于另一个目录的 workspace 请求。不开放 file:// 跨站写入。AI 工作流不依赖本机网址或服务进程。

浏览器文件来源及保存权限依据：[MDN 同源策略](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)、[MDN File System API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API)。本工具选择本机服务，从而不要求用户每次选择文件写入句柄。

## Momo 样本评估

当前 design-system.json 已记录 PAPER POP / VOLT 的主要画刷、界面与读数字体、部分圆角和间距、300ms 动效。来源为项目当前 C#/XAML，保留未映射默认值的明确标签。guidelines/import-baseline.json 是本次导入基线，供后续三方比较，浏览器不会编辑它。

通用网页样本无法替代 WPF 实际渲染。本次没有重设计 Momo、修改产品源码或重建 MomoMonitor.exe，也没有提交代码应用报告。必须另行构建和检查原生界面，才能确认某个设计修改已反映到 EXE。

## 验证范围

接口回归涵盖版本保存、并发冲突、跨站拒绝、外部文件更新、应用证据及跨项目链接隔离。JavaScript 另做语法检查。

已在 App 的本机页面完成提示词弹窗、复制反馈、教程入口与视觉布局检查；程序测试同时覆盖保存、冲突与跨项目隔离。
